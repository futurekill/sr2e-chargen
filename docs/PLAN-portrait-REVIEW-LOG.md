# Plan Review Log: portraits

## Round 1 — Codex gpt-6-sol high
## Findings

- **Decoder exposure:** Checking `metadata().format` happens after sharp has opened the input, so SVG and other unwanted loaders can still see hostile files; reject files by byte signature before calling sharp, then require the detected format to match the declared MIME type. [Portrait plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:18) [Sharp input formats](https://sharp.pixelplumbing.com/api-constructor/)
- **Memory exhaustion:** The child’s 256 MB V8 heap limit does not bound sharp’s native allocations, and sharp says its pixel limit trusts image metadata; add an OS memory limit for image processing, lower the pixel cap to the needed size, and test compressed bombs against that limit. [Worker limits](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/sheet/index.mjs:12) [Sharp limits](https://sharp.pixelplumbing.com/api-constructor/)
- **Upload parsing:** The app currently accepts JSON bodies only, so the proposed raw-image PUT needs an explicit, route-scoped binary parser; register one for the three MIME types with the 8 MB limit and reject empty or mismatched content. [App parsers](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/app.mjs:25) [Upload plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:10)
- **Idempotency:** The existing fingerprint hashes JSON, while a portrait request is binary; bind the key to the document ID, revision, MIME type, and SHA-256 of the complete upload, and recheck the revision inside the asset transaction. [Library](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/library.mjs:38)
- **Asset IDOR:** An `assetId` in a document body must never authorize a lookup by itself; fetch image bytes only where asset ID, document ID, and owner ID all match the authorized document, returning the same 404 for missing or mismatched assets. [Serving plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:42)
- **Quota and retention:** `bytes` is undefined for the two stored encodings, and the five-asset eviction must be part of the same accounting operation; define it as `webp.length + jpeg.length`, charge once per asset rather than per revision, and atomically subtract only assets actually deleted. [Storage plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:27) [Current quota](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/library.mjs:58)
- **Purge race:** Existing purge selects deleted documents, then deletes by ID without rechecking `deleted_at`, so a concurrent restore can be purged along with its portraits; lock each candidate and condition the delete on the purge cutoff before adjusting counters. [Purge](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/library.mjs:205)
- **Cross-database bytes:** The migration must select SQLite `BLOB`, PostgreSQL `bytea`, and MySQL/MariaDB `LONGBLOB`, while copy and checksum code must normalize driver-returned binary values; add round-trip, migration-restart, copy, and restore tests on all four databases, including a two-image row near the size cap. [Migration pattern](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/db/migrations/001-initial.mjs:8) [Database rule](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN.md:350)
- **Backups and metadata:** Putting assets in the database gives a consistent snapshot but does not implement the required asset-checksum manifest or restore verification; add those checks and inspect parsed EXIF, XMP, and ICC fields in both outputs rather than searching for text. [Backup rule](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN.md:360) [Proposed tests](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:57)
- **Container delivery:** Prebuilt sharp packages can work with `ignore-scripts`, but they depend on platform-specific optional packages, and the current Dockerfile copies build-stage modules into a different Debian runtime; pin sharp, verify optional packages in the lockfile, and smoke-test an actual conversion in the final image for each supported architecture. [Dockerfile](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docker/Dockerfile:6) [.npmrc](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/.npmrc:1) [Sharp installation](https://sharp.pixelplumbing.com/install/)
- **Simpler storage option:** Two permanent encodings double asset accounting and backup work; consider storing only the sanitized WebP and generating the PDF JPEG inside the already bounded render job, then measure the added render cost. [Storage and sheet plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-portrait.md:24)
