# Plan Review Log: the Workshop (Vehicle Workshop part 2)
Started 2026-11-26. MAX_ROUNDS=5. Codex model gpt-6-sol (high for r1).

## Round 1 — Codex

**Verdict: the plan needs revision.** The Foundry Workshop will reopen an imported actor when `system.design.version` is 2 and its choices are present. It recognizes design mods by `flags.sr2e.designMod` and retains them by item ID. `wsUid` is used to match newly created items during a save; it is not required to reopen an existing item ([Workshop constructor](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:125>), [mod reconciliation](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:505>)).

1. **The design tables would not reach the server.** Adding the JSON paths to `WANTED` is insufficient: `selectPaths` discards them, and the runtime catalog has no design-table artifact ([content selection](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/tools/content.mjs:89>), [catalog loading](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/catalog.mjs:20>)). **Fix:** Include the three files in selected content, build a checksummed table artifact, and load that artifact at startup.

2. **“Shape of `blankDesign()`” rejects real Workshop choices.** `tires`, `quality`, and `dbwSplit` are used by the Workshop but absent from `blankDesign`; the proposed nested `markUp` rule also needs distinct boolean and numeric fields ([plan](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:51>), [Workshop fields](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:277>)). **Fix:** Define an explicit versioned choices schema with those optional fields, field enums, per-field ranges, and own-property checks.

3. **The proposed numeric bound permits purchasable nonsense.** With real R2 tables, `speed: -10000` produces Speed **−9,925**, `valid: true`, no problems, and a 4,000¥ price; the engine checks the maximum but not that resulting Speed is nonnegative ([engine](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/vehicle-design.mjs:509>)). **Fix:** Validate choice deltas against table starts and resulting stat minimums before treating a design as finished or buyable.

4. **Draft rebuilding is undefined.** A new blank design has no chassis or plant, so `designVehicle` returns no usable stats and `workshopUpdate` cannot take valid `ch` and `pp`; yet the plan promises rebuilding and export after every op ([plan](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:42>), [early return](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/vehicle-design.mjs:486>)). **Fix:** Specify a separate draft actor shape that stores v2 choices, and apply `workshopUpdate` only when both table rows exist.

5. **Rebuilding omits artwork and can misrepresent modded stats.** Foundry applies `chassisArt` outside `workshopUpdate`; the proposed pure extraction does not include it. Its saved actor holds *base* stats, while Foundry derives mod effects on preparation, so the app’s existing vehicle page and character sheet will display base values ([save](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:474>), [data model](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/data/actor-data.mjs:2264>), [sheet row](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/sheet/model.mjs:108>)). The Workshop does not currently write `design.traits`, despite the data-model comment saying it does. **Fix:** Apply chassis art and token dimensions on creation, preserve any actor-only fields deliberately, and derive displayed effective stats from the mods.

6. **The mod rules are more than a static filter or a rating range.** Foundry loads every `vehicle_mod`, then disables choices using `designable` and build-dependent `modProblems`; `maxRating` can be a formula, and some rated mods have no authored maximum ([picker](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:287>), [restrictions](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/vehicle-design.mjs:304>)). The eligibility calculation and `choiceFor` can both be pure if passed the design, tables, and mod data; compendium loading stays in the app. **Fix:** Extract those parameterized functions and enforce their result again in the reducer.

7. **DBW preview and saved items can disagree.** Foundry clears a design mod’s `custom.choice` for engine preview so the working `design.dbwSplit` controls the result, then writes the split onto the DBW item at save ([engine mods](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:190>), [save choice](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:512>)). Passing saved mod choices directly to `designVehicle` breaks that behavior. An arbitrary eight-key numeric object is also too broad for an exported item choice. **Fix:** Use Foundry’s preview transformation and validate DBW’s three whole-percent fields and sum of 10; allow other choice fields only when a mod rule defines them.

8. **Price and purchase need explicit gates.** Engine price includes `designNuyen` *after* DP × Mark-Up and rounding, which the plan’s price description omits ([price calculation](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/vehicle-design.mjs:668>)). More seriously, `garageOf` supplies only source and price, and `buyGarageVehicle` checks only positive prices: neither checks design validity or whether the character has R2 enabled ([garage snapshot](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/library.mjs:131>), [purchase](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/shared/creation.mjs:366>)). **Fix:** Recompute validity and full engine price in the purchase transaction, require R2 in the character’s books, and keep R2 marked in use while its purchase receipt remains.

9. **The export loses compendium mod fields.** Catalog building removes prose such as `system.notes` into `entry.text`, while the plan proposes exporting `entry.system` as the item snapshot; Foundry creates its Workshop mods from the full compendium system ([catalog shaping](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/tools/build-catalog.mjs:114>), [Foundry mod creation](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:432>)). **Fix:** Preserve or reconstruct a full exportable mod source, with its notes and source metadata, before embedding it.

## Round 2 — Codex

The revision fixes the round 1 assumptions about reopening: Foundry loads v2 choices, recognizes flagged design mods, and does not require `wsUid` on imported items. The #9 rejection also holds for the app’s established rule-data export contract; the source UUID does not itself restore prose, but missing prose does not prevent the Workshop from editing the mod.

Material problems remain:

1. **Artwork disappears during rebuilding.** The plan rebuilds from a fixed minimal actor after every design op but applies `chassisArt` only when the chassis is first chosen or changes. A later design or mod edit loses the image and token footprint; choosing a chassis before a plant may never apply them. [Plan](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:54>), [Foundry save](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/apps/vehicle-workshop.mjs:474>). **Fix:** Derive chassis art on every rebuild from the selected chassis, or explicitly carry it forward.

2. **The promised R2 book lock is not wired to the existing guard.** The plan adds `books: ["r2"]` to a purchase receipt, but `booksInUse` currently reads only a vehicle source’s citation, not receipt books. A designed vehicle need not have an R2 citation, so the character can turn R2 off after buying it. [Plan](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:86>), [guard](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/shared/creation.mjs:666>). **Fix:** Make `booksInUse` include each vehicle receipt’s `books`, and test the toggle after purchase.

3. **Mods from other books bypass character book choices.** The picker permits every catalog `vehicle_mod`, while purchase checks only R2. A design containing a mod from another sourcebook can therefore be bought with that book disabled. [Plan picker](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:48>), [purchase rule](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:86>). **Fix:** Record the installed mods’ sourcebooks and require all of them at purchase, then keep them in use through the receipt.

4. **The proposed `setDesign` request conflicts with the current operation schema.** The route’s `choices` field allows at most four primitive properties; a Workshop design is a larger nested object. The create route also requires `catalogId`, so `{ design: true, name }` is rejected before the reducer runs. [Route schemas](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/routes/documents.mjs:22>), [plan ops](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:67>). **Fix:** Specify separate bounded route schemas for the design creation request and `setDesign`, with reducer validation as the second check.

5. **Effective-stat parity needs the Foundry context.** The plan names `applyModEffects`, but its results depend on category, transport status, Body, Pilot, and tires. Calling it with only base stats and mods can print different handling and other effects from Foundry. [Plan](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-workshop.md:95>), [Foundry preparation](</Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/data/actor-data.mjs:2271>). **Fix:** Define one shared effective-stat adapter that constructs the same context for the vehicle page, sheet row, and stat block.

VERDICT: REVISE
