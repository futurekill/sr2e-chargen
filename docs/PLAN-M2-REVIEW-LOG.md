# Plan Review Log: milestone 2 — create a character
Started 2026-11-16. Codex gpt-6-sol, high effort, a fresh session per round.

## Round 1 (REVISE, 13 findings)
1. **Programs cost no Resources.** The plan relies on `chargenSpend`, but its resource type list excludes `program`, despite core programs being purchasable gear. A decker can finish with expensive programs uncharged. [Rules](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/sr2e-rules.mjs:1498) · **Fix:** Include programs in the creation budget and price their configured ratings.

2. **Lifestyle costs also disappear.** The catalog lifestyle has `monthlyCost` and `monthsPaid`, while `chargenItemCost` reads `cost` and `quantity`; the plan’s `setLifestyle { catalogId, months }` does not bridge them. [Lifestyle source](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/packs-src/lifestyles/Low_4aebdc396c991dfd.json) · **Fix:** Charge `monthlyCost × monthsPaid` and set both the lifestyle item and `actor.system.lifestyle`.

3. **Extras are incomplete and buddy pricing is wrong.** The plan prices each contact beyond two at ¥5,000, including the buddy; the rules price a buddy at ¥10,000 and also allow a gang or tribe and followers. [Creation rules](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/RULES-CHARGEN.md:59) · **Fix:** Model and charge each extra at its stated price, with the one-buddy limit.

4. **The allergy option has no workable budget model.** The rules grant separate, selectable bonuses for allergy category and severity. The plan names an `allergies` option and says “one bonus category each,” but defines neither those selections nor how their Attribute, Skill, Force, or nuyen bonuses enter the allotments. [Creation rules](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/RULES-CHARGEN.md:72) · **Fix:** Store the allergy, severity, and two bonus choices explicitly and add their amounts before budget validation.

5. **The core-only scope is unenforced.** `addItem` rejects some item types but does not restrict the book; catalog search contains sourcebook items, while sourcebooks and book toggles are deferred to M5. [Plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-M2.md:56) · **Fix:** Enforce the permitted book set on the server for every catalog-backed operation.

6. **Configured item prices need more than the proposed choices.** `derivedItemCost` needs fields such as a program’s `multiplier`, a skillsoft’s category, and context for weapon foci and ware; the sheet’s budget projection supplies additional ware context. The plan’s generic `addItem { rating, grade, quantity, force }` and catalog copy do not specify that recomputation. [Cost function](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/rules/sr2e-rules.mjs:2480) · **Fix:** Define per-type purchase projections and derive price and Force cost server-side from catalog data and selected context.

7. **`setItem` can undermine catalog authority unless its fields are closed.** Copying an item on `addItem` does not protect a later edit to `system.cost`, `bondingCost`, `allocated`, or `freeLanguage`; those fields directly affect finish validation. [Budget projection](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/sheets/actor-sheet.mjs:531) · **Fix:** Allowlist editable fields by item type and recompute rule fields after every operation.

8. **Existing library routes bypass the finish freeze.** `PUT /:id` calls `updateDraft` without a kind check, so it can replace a character body with draft JSON; revision restore can bring back a pre-finish body. Both bypass the proposed operations route. [Library](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/server/library.mjs:102) · **Fix:** Enforce kind and lifecycle rules in every existing mutation path, including revision restore.

9. **Finish does not commit playable cash.** The plan records leftover nuyen and dice in `creation.finished`, but the Foundry-shaped actor’s spendable cash is `system.nuyen`, and creation status is `system.chargen.inProgress`. A finished document could therefore show zero cash or remain in creation when used later. [Actor shape](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-foundryvtt/module/data/actor-data.mjs:259) · **Fix:** In the same conditional transaction as the roll, store starting money in `actor.system.nuyen` and end `chargen.inProgress`.

10. **“Pure reducer” and random finish conflict.** `applyOp` cannot both be pure and call `crypto.randomInt`; the plan does not locate the roll relative to validation, the conditional write, and the stored idempotent response. [Plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-M2.md:52) · **Fix:** Keep validation and reduction pure; perform and persist the dice roll only inside the successful finish transaction, then return its stored response on replay.

11. **The catalog copy is not the claimed Foundry source shape.** Text fields are removed from `system` during catalog build, the proposed top-level `catalog` metadata is outside the item data model, and `img` paths point into Foundry assets that the content sync does not copy. Thus descriptions and images will not survive or display as claimed. [Catalog shaping](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/tools/build-catalog.mjs:114) · **Fix:** Define an explicit export mapping, keep provenance in a supported flag, and serve or replace image assets.

12. **The parity test cannot validate the creation gate.** Seven pregen derived-value snapshots say nothing about program and lifestyle spending, contact prices, allergy bonuses, operation tampering, or finish retries; regenerating snapshots when the pin moves can also bless a shared regression. [Plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-M2.md:94) · **Fix:** Add rule-level creation fixtures and transactional finish tests alongside the derived-value parity snapshots.

13. **The import-boundary test is not a code safety boundary.** Static imports staying under `module/rules/` and `module/config.mjs` do not prevent side effects or dynamic imports within copied executable code, which the plan runs on both server and client after content sync. [Plan](/Users/jcandalino/Code/foundryvtt/shadowrun/sr2e-chargen/docs/PLAN-M2.md:25) · **Fix:** Copy only the required dependency closure and require explicit review of executable-code changes before updating its pin.
